# CDB WatchDog 使用說明

1. 主畫面上方保留 109.123.238.225:1883，按「連線 MQTT」。手動發布頁已隱藏。此 Broker 沿用一般 MQTT、無帳密；沒有加入 TLS。警報／恢復預設 Topic 為 ncku/watchdog/alert、ncku/watchdog/recovery。
2. 「CDB 監控／通知」填入 SQL Server、資料庫、SQL 帳密，或選 Windows 驗證。密碼遮罩且不寫入設定檔。SQL 預設加密並驗證憑證；僅在確認可信任的自簽 SQL 伺服器時勾選信任憑證。
3. 查詢間隔預設 10 秒，無新資料門檻 120 秒，另有獨立「查詢逾時」預設 10 秒（1～600 秒），涵蓋單次 DB 連線／SQL 嘗試。每輪工作完成後都會完整倒數查詢間隔（例如 10、9、8……1），再開始下一次查詢；不重疊或補跑 Query。警報、恢復通知各有開關、Topic 與多行文字框；可以輸入純文字或 JSON，通知不強制驗證 JSON。
4. 按「開始監控」。第一次成功查詢建立基準，從此刻起算，不依舊資料日期立刻告警。空表或 TIMETAG 全 NULL 也會建立基準。
5. 停止監控後才可修改設定。停止／重新開始會重建基準。啟動時自動讀取 exe 旁 system.ini 的 CDB 資訊；[CDB] 可設定 QueryTimeoutSeconds=10。介面修改不自動寫回檔案，其餘通知／時間設定重開回到預設值。

唯讀 SQL：`SELECT MAX([TIMETAG]) FROM [dbo].[VM_RESULT_CONTROL];`。需有此表 SELECT 權限；沒有寫入或建索引操作。監控整張表，不分設備。只有 MAX(TIMETAG) 向前增加視為新資料；相同／倒退時間的新增列無法偵測。資料生產端須保證 TIMETAG 遞增；大量資料建議由 DBA 評估 TIMETAG 索引。

每次成功查詢才做告警判斷，因此正常查詢下觸發時間約為門檻後一個查詢間隔內。查詢失敗只顯示 DB 異常，不觸發資料逾時判斷；恢復查詢後如有新時間則重置，否則依原基準計時（包含中斷期間）。DB 錯誤目前不另外發布 MQTT。

逾時事件只產生一次；新資料後產生一次恢復事件（如開啟）。兩者以 QoS 1、不保留發布。變數：`{timestamp}` 事件時間、`{seconds}` 本次無新資料觀察秒數、`{lastData}` 最新資料庫時間（沒有則空字串）、`{lastReceived}` 最近一次觀察資料更新／首次基準的本機時間。

MQTT 斷線不停止 DB 監控，通知按事件順序暫存記憶體，最多 100 筆，滿時停止監控避免無限增長；需手動重新連線 MQTT，監控執行中於下次輪詢重試。停止监控保留待送通知，關閉程式會遺失。重試可能重複送達（QoS 1），接收端應做去重。重新開始監控不會清掉先前待送內容。

本次未連線正式資料庫或發送正式警報；測試程式只驗證計時狀態與視窗建立，不等於現場端到端驗收。正式 Topic 與內容格式仍需和東元確認。

每輪最多送一筆待送通知。發布前嘗試訂閱同一 Topic，發布後最多等待 10 秒確認相同內容；結果顯示於 Log。訂閱驗證失敗不導致已成功發布的通知重送，也不代表東元的業務接收程式是否處理。
