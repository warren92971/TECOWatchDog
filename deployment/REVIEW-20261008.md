# WatchDog 程式 Review（2026-10-08）

範圍：TESCWatchDog 所有 C# 原始碼、Designer、專案設定、INI 範本，以及離線檢查程式。未連線正式 CDB 或發布 MQTT 業務訊息。先前獨立的 RabbitMQ 安裝包不屬於目前 WatchDog 執行流程。

## 已修改

- 查詢間隔與查詢逾時獨立。Designer 新增「查詢逾時（秒）」1～600，預設 10；INI 的 `[CDB] QueryTimeoutSeconds=10` 可覆寫。既有 INI 無此欄位可正常使用。
- 每次 DB 嘗試用一個 linked CancellationToken 計算連線與 SQL 的總逾時，並保留 SQL CommandTimeout。SQL 連線自身最多 10 秒（若總額度更小則跟隨），停用 SqlClient 隱含重連；取消的實際完成仍取決於驅動程式回應，不強制中斷執行緒。
- 每輪工作完成後固定等待完整查詢間隔，狀態列逐秒倒數；不重疊查詢、不補跑錯過週期。
- DB 查詢失敗／逾時只記錄 DB 異常，不執行該次無資料狀態判斷。恢复成功後若 TIMETAG 沒更新，仍依上次成功基準判斷（含中斷期間）。
- 每輪最多處理一筆通知，避免 Broker 恢復後排空大量通知拖延 DB 輪詢。整輪耗時包含發布時間；這不是精準即時排程。
- 修正訂閱與發布共用逾時預算的問題：訂閱驗證上限 5 秒、發布上限 10 秒、外層總預算 20 秒。訂閱失敗仍能嘗試發布。
- 修正 QoS 0 接收逾時紀錄不應宣稱 Broker 已 ACK。警報仍固定使用 QoS 1。
- MQTT 連線失敗後的清理例外現在會被捕捉；關閉視窗後不再由按鈕非同步 finally 更新已釋放的控制項。連線期间鎖定 Broker／Port，避免畫面資訊與實際連線不一致。
- 補充計時、取消、回呼執行緒、待送佇列、INI 密碼解析等關鍵註解，保留 Designer 可編輯結構。

## 尚有的設計限制

- MAX(TIMETAG) 只能偵測時間向前的資料；回填舊時間、同時間新增、刪表後重建低時間資料都可能無法當成恢復。若要逐筆準確偵測，需先確認遞增 ID／資料來源規則。
- 無資料／恢復通知為記憶體佇列，最多 100 筆；程式關閉後不保留，滿時停止監控。正式持久化與溢位政策需要另定。
- 接收驗證按 Topic + 完整 payload 比對，排除 retained 快照；其他發布者恰好傳一模一樣內容仍無法區分。若需要嚴格端到端識別，需雙方約定 message_id；不擅自修改東元的訊息格式。
- MQTT 中斷目前需手動重連；QoS 1 重試可能重複送達，東元接收端需容忍重複。
- 收到 Broker 回傳不代表東元業務程式已處理；這需要對方另回覆 ACK Topic。
- SQL 密碼在 system.ini 為明文（已被 Git 忽略），MQTT 沿用既定的無帳密／無 TLS 設定。

## 驗證

離線測試涵蓋正常間隔、超時冷卻、快速失敗冷卻、INI 逾時範圍與向後相容、無資料及恢復狀態、Topic/payload 匹配與 retained 排除、斷線清理及實際 WinForms 離屏繪製。正式 SQL Server 的網路超時與取消行為仍需現場驗收。
